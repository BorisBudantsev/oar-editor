# Архитектура приложения

Краткое описание структуры проекта «Редактор графика ОАР». Для разработчиков,
которые будут сопровождать или расширять приложение.

## Общая идея

Настольное Windows-приложение на PyQt5. Работает локально, без сервера.
Данные хранятся в двух форматах:

- **Проекты графика** — отдельные JSON-файлы (один файл = один месяц).
- **Служебные данные** — общая база SQLite `app_data.db`: справочник
  сотрудников, настройки, автосохранение.

## Модули

### `main.py`
Создаёт `QApplication`, устанавливает иконку, открывает главное окно.
Учитывает работу и из исходников, и из собранного `.exe`.

### `models/`
- **`project_model.py`** — модель графика: месяц, год, сотрудники, служебные
  строки. Умеет сериализоваться в JSON и обратно. Единственный источник
  правды о текущем проекте.
- **`employee_model.py`** — работа со справочником сотрудников в SQLite.
- **`autosave_model.py`** — автосохранение последнего состояния.

### `controllers/`
- **`project_controller.py`** — связывает модель с таблицей `QTableWidget`.
  Строит таблицу, применяет заливку выходных и ошибок, управляет выделением
  и очисткой дней. Содержит карту строк `row_map` — соответствие между
  строками таблицы и данными модели.
- **`export_controller.py`** — экспорт графика и отчётов в HTML, Excel,
  Word, PDF. Функции без состояния.
- **`undo_commands.py`** — команда `CellEditCommand` для отмены одного
  изменения ячейки. Используется вместе с `QUndoStack`.

### `utils/`
- **`constants.py`** — все константы: коды, категории, месяцы, версия формата.
- **`database.py`** — подключение к SQLite, создание таблиц, миграции.
- **`storage.py`** — сохранение и загрузка JSON-проектов с валидацией.
- **`validation.py`** — правила проверки графика. Возвращает список ошибок.
- **`analytics.py`** — анализ загруженности: статистика по сотрудникам,
  по рабочим местам, общий итог.

### `views/`
- **`main_window.py`** — главное окно: меню, панель инструментов, таблица,
  строка состояния. Обрабатывает сигналы, управляет автосохранением,
  валидацией, диалогами.
- **`dialogs.py`** — мастер создания проекта и диалог добавления сотрудника.
- **`delegates.py`** — делегат ячейки `ScheduleDelegate`. Определяет список
  допустимых значений в выпадающем списке в зависимости от категории
  сотрудника и текущего содержимого ячейки.
- **`validation_dialog.py`** — окно со списком ошибок.
- **`stats_dialog.py`** — окно анализа загруженности с тремя вкладками
  и кнопками экспорта.

## Поток данных

### Изменение ячейки
1. Пользователь кликает по ячейке → открывается делегат с выпадающим списком.
2. Выбор значения → `QTableWidgetItem` обновляется.
3. Сигнал `cellChanged` → `MainWindow.on_cell_changed`.
4. Создаётся `CellEditCommand`, пушится в `undo_stack`.
5. Команда пишет значение в модель → контроллер пересчитывает валидацию →
   автосохранение в SQLite.

### Сохранение проекта
1. `Ctrl+S` → `storage.save_model_to_file` пишет JSON на диск.
2. Модель помечается как «чистая» (`mark_clean`).
3. Автосохранение сбрасывается — актуальная версия теперь в файле.

### Автосохранение
1. Каждое изменение модели → `AutosaveModel.save(model.to_json())`.
2. При запуске `_try_restore_autosave` проверяет наличие записи.
3. При согласии пользователя — восстановление из SQLite.

## Формат JSON-проекта

```json
{
  "version": "1.0",
  "month": 8,
  "year": 2026,
  "employees": [
    {"id": 1, "name": "Иванов", "category": "permanent",
     "days": ["З", "Б", "Д", ""]}
  ],
  "special": {"Э": ["3", "3"], "О": ["3", "3"]},
  "nextId": 5
}
month — 0 (январь) … 11 (декабрь).

category — permanent или parttime.

days и массивы в special — одинаковой длины, равной числу дней месяца.
Ограничения
Undo/redo работает только с ячейками. Удаление сотрудника, смена категории,
очистка дня не откатываются.

Состав сотрудников задаётся только мастером при создании проекта.

Формат JSON не поддерживает миграции между версиями — при смене
PROJECT_VERSION старые файлы не откроются.
Как расширять
Новый код назначения — добавьте в utils/constants.py в соответствующий
список (CODES_ENDO, CODES_OPERATION). Остальные модули подхватят его
автоматически.

Новое правило валидации — добавьте проверку в utils/validation.py
в функцию check_day. Подсветка, диалог и tooltip обновятся сами.

Новый формат экспорта — функция в controllers/export_controller.py,
пункт в меню «Экспорт» в views/main_window.py.
